# `scripts/fix-zed-transparency.sh`

`zed/themes/dank-zed-theme.json` is generated by matugen from the current wallpaper colors (`matugenTemplateZed` in [`DankMaterialShell/settings.json`](../DankMaterialShell/settings.json)). Every regeneration — which happens on a wallpaper/color change — resets the "DankShell Dark Transparent" theme's backgrounds back to matugen's own defaults (mostly opaque, with the root `background` field reset to `null`), wiping out this repo's transparency tuning. `fix-zed-transparency.sh` reapplies it.

> [!NOTE]
> It edits colors by alpha percentage, not by hardcoded hex value, so it works no matter what base color matugen picked from the new wallpaper. Running it twice in a row is a no-op.

## Usage

Run this after a wallpaper or theme change if Zed looks fully opaque again:

```bash
./scripts/fix-zed-transparency.sh
```

`init.sh` also symlinks it to `~/.local/bin/fix-zed-transparency` (no `.sh`), so after setup it's callable from anywhere as `fix-zed-transparency`.

## What it does

Within the "DankShell Dark Transparent" theme block only (the light variant and the non-transparent themes are left untouched):

1. **Bars** (`status_bar`, `title_bar`, `toolbar`, `tab_bar`, tabs) — set to `99` alpha (~60% opacity).
2. **Workspace** (`surface.background`, the root `background` field, `panel.background`, `editor.background`/`gutter`/`subheader`, `terminal.background`) — set to `BF` alpha (75% opacity), more solid than the bars so code stays easy to read. The root `background` field is seeded from `surface.background`'s color, since matugen resets it to `null` rather than a color.
3. **Context menus** (`elevated_surface.background` — right-click menus, command palette, file finder) — alpha stripped entirely so popups stay fully opaque and readable.
4. **`background.appearance`** — reset to `"blurred"` in case matugen changes it, so Zed still requests OS-level blur (harmless no-op under niri, which doesn't support it, but matches the intent).

The root `background` field is located by its position immediately after `surface.background`, not by matching the key name `background` — that name also appears in each entry of the theme's `players` array (multiplayer cursor colors), which must not be touched.
